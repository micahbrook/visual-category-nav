Review of the current homepage code (HomeHTML)

  1. The scrollbar rules aren’t scoped. ::-webkit-scrollbar, -thumb and -track are global, so every scrollbar on the site turns 2px grey. The new block hides only its own scrollbar.
  2. The rail is on the page twice. A second .visual-nav sits inside the what-is-on-banner block. Remove both when this goes in.
  3. Dragging opens tiles. The jQuery drag never cancels the click that ends a drag, so a drag can open a category. The new script swallows that click.
  4. No arrows, no keyboard support, no landmark. Tiles are bare <a> tags in a div, with no list, no nav and no label, and there’s no way to page with a mouse. The new block is a labelled nav with a ul, GEL arrows and focus rings.
  5. The values don’t come from the GEL. #000, #ccc, 1.5rem, a 148px minimum width and a fixed 161px height (which cuts three-line labels), and font-family: Lato with no fallback. Every value in the new block is a GEL token or a Figma component size.
  6. The content is still placeholder. Every href is # and every tile uses the same Galaxy S26 image.
  7. The selectors are global. .drag-scroll, .container and the jQuery binding can collide with other blocks. Everything in the new block is under .hn-vcn.
  8. Images shift the layout. The images have no width or height and no lazy loading. The new tiles have fixed boxes and lazy-load the images out of view.
  9. The container doesn’t match the page. Bootstrap .container steps 540–1920 with 24/32 padding, so the rail misses the 1440 · 16/24/32 page container below it. The new block uses that container’s exact box.
  10. No focus styles. There’s no :focus-visible state. draggable="false" is fine, and the new block keeps it.
