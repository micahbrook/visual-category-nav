Black Friday Launcher: dev handoff

The Black Friday Launcher, the seasonal homepage category row for harveynorman.com.au, ready for the CMS. It is separate from the everyday Category Launcher and replaces it for the event. Design: Lawrence’s Peak Trade 2026 row, in Templates 1.0 › Visual Category Navigation 0.1 (Figma file zgmSEjTOBbFh54YaVjeuhI, frame Category Rail, node 26738:39271). GEL tokens, theme hn. Concept for review, 5 November 2026, not yet signed off.

To put it live

  1. Upload the images below to media/wysiwyg/visual-category-nav/ (the code already points there).
  2. Paste one block into the homepage rich-content CMS block straight after the lead space (the .hn-slider div). Replace the current .visual-nav markup, its <style> and its jQuery drag-scroll script, and remove its second copy in the what-is-on-banner block.
  3. When Black Friday ends, put the Category Launcher (the everyday block, its own handoff) back in place of this one.

How it’s built

  • One tile pattern. Every tile is a link, one image and a label. Each image is the whole 134px tile (88px on phones) at 2x, a 268 × 268 PNG with the BLACK FRIDAY tag drawn in, as Lawrence designed it. To change a tile, export it from Figma at 2x and upload it under the same name; nothing in the code changes.
  • Self-contained. Markup, a scoped <style> and a plain <script>: no jQuery, no site CSS. Container queries set the sizes, so it fits wherever it’s pasted.
  • Accessible. Tested against WCAG 2.2 AA; details below. Please keep the role="list", the skip link, the arrow labels and the empty alt on tile images when you change it.
  • Fullstory. Tiles carry data-fs-element="Category Launcher Tile", data-category and data-position. When Fullstory is on the page, the script sends Category Launcher Tile Clicked, Category Launcher Arrow Clicked and Category Launcher Scrolled. Each carries the version (everyday or black-friday); tile clicks also carry the category, its position and its link.

Accessibility, tested 5 November 2026

This block passes axe-core (WCAG 2.2 A and AA rules) at 375, 768, 1024, 1440 and 1920px. These checks cover what automated tools miss:

  • Screen readers (VoiceOver, NVDA, TalkBack). The rail is a navigation landmark, “Shop Black Friday deals by category”, holding a list of 8 links, each named by its label (“Top Black Friday Deals”, “TV & Audio Black Friday Sale” and so on). Tile pictures are decorative (alt="") so the label isn’t read twice. role="list" keeps the list announced in Safari, which otherwise drops it when bullets are removed.
  • Keyboard only. The first Tab stop is a “Skip categories” link that appears on focus and jumps past the rail. Every tile and arrow shows a 2px focus ring 2px outside it. A tile that takes focus under an arrow, or past the rail’s edge, scrolls fully into view.
  • Low vision. No sideways page scroll at 320px, the same as 400% zoom; only the rail itself scrolls. With WCAG text-spacing overrides, no label clips or overlaps. Labels are 11.9:1 against white, and the focus ring is near-black on white.
  • Windows high contrast. Tiles and arrows keep a visible edge when the page’s own colours are replaced.
  • Colour. Nothing relies on colour alone: every label says what the tile is in words.
  • Motor. Tiles are at least 88 × 136px and arrows 44 × 44px (WCAG asks for 24 × 24). Dragging is never required: mouse users get the arrows from 640px wide, and touch screens scroll natively.
  • Motion. With reduced motion on, the arrows move the rail instantly instead of animating. Nothing moves on its own.

Not yet tested: a session with real assistive-technology users, and VoiceOver on an actual iPhone. Worth doing before launch. The BLACK FRIDAY tags and the lead tile’s BLACK FRIDAY SALE tag are pictures of text; each tile’s label gives the words as text, so nothing is lost.
